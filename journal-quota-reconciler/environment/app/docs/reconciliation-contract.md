# Journal quota reconciliation contract

`journal-reconcile --inventory <file> --policy <file> --output <directory>` reconciles persistent journal namespaces sharing storage. Inputs are JSON. All byte quantities are non-negative integers.

The inventory has `filesystems` (`id`, `io_domain`, `capacity_bytes`, `free_bytes`) and `namespaces` (`name`, `filesystem`, `usage_bytes`, `oldest_unix`, `vacuum_after`). Names and I/O domains are non-empty; filesystem ids and namespace names are unique; filesystem and dependency references must resolve. `vacuum_after` is a duplicate-free array of other namespace names. The complete namespace dependency graph must be acyclic.

The policy has positive integer `vacuum_parallelism`, `filesystems` keyed by id (`reserve_bytes`, `budget_bytes`, and `pools`), and `namespaces` keyed by name (`pool`, `floor_bytes`, `cap_bytes`, `weight`, `priority`). Each pool is keyed by name and has `floor_bytes`, `cap_bytes`, and `weight`. Pool names are non-empty and local to one filesystem.

Every inventory object must have exactly one policy entry, with no extras. Every namespace pool reference must resolve on its filesystem, and every declared pool must have at least one namespace. Weights are positive integers, priorities are non-negative integers, floors do not exceed caps, reserve does not exceed capacity, and budget does not exceed `capacity-reserve`. On each filesystem, pool floors must fit the allocatable total. Within each pool, the sum of namespace floors must fit the pool floor. Invalid input or an unwritable output must exit nonzero without creating or changing the output directory.

For each filesystem independently, its allocatable total is `min(budget_bytes, capacity_bytes-reserve_bytes)`. Allocate that total among its pools using capped weighted max-min allocation: start every pool at its floor, repeatedly give each active pool `floor(remaining * weight / active_weight)` bytes limited by its remaining cap, then give undistributed remainder bytes one at a time in ascending pool-name order among active pools. Repeat until no space or no active pool remains.

Next, allocate each pool's allocation among its namespaces by the identical procedure, starting at namespace floors, using namespace caps and weights, and breaking remainder ties by ascending namespace name. Capacity left because every pool is capped is filesystem-unallocated. Capacity assigned to a pool but left because every namespace in it is capped is pool-unallocated and is also filesystem-unallocated; it is never transferred to another pool. Both allocation stages use integers and are normative.

A namespace needs vacuuming when usage exceeds its allocation. Schedule required actions into waves numbered from zero. A namespace cannot be scheduled until every required action named by its `vacuum_after` has completed in an earlier wave; dependencies that do not need vacuuming are already satisfied. At the start of each wave, collect all dependency-ready actions and order them by descending priority, then ascending `oldest_unix`, then ascending namespace name. Scan that fixed ready list once, selecting at most `vacuum_parallelism` actions and at most one action per `io_domain`. Actions skipped because their I/O domain is already used wait for a later wave, and actions unlocked during a wave cannot enter that same wave. The `vacuum` array is wave order, then selection order. Each action records `wave`, `namespace`, `filesystem`, `usage_bytes`, `target_bytes`, and `reclaim_bytes=usage_bytes-target_bytes`.

Replace the output atomically with exactly these artifacts: `plan.json` and one `journald/<escaped>.conf` per namespace. Escape namespace names using systemd's filename rule: ASCII letters, digits, `_`, and `.` remain; every other UTF-8 byte becomes `\\x` plus two lowercase hex digits. Each config is exactly `[Journal]\nSystemMaxUse=<allocation>\nSystemKeepFree=<filesystem reserve>\n`. `plan.json` is UTF-8 canonical JSON: keys recursively sorted, compact separators, integer numbers, arrays in the orders above, and one trailing newline. Its object has `filesystems` and `vacuum`. Filesystems are in id order and each has `id`, `allocatable_bytes`, `allocated_bytes`, `unallocated_bytes`, and `pools`. Pools are in name order and each has `name`, `allocation_bytes`, `allocated_bytes`, and `unallocated_bytes`. Here `allocated_bytes` always means bytes ultimately allocated to namespaces.
