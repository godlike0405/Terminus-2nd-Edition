# Task Explanation — Evaluate and harden SPF/DMARC against spoofing

_Category: Security. Reviewer-facing; lives at the task root, not shipped to the agent (which sees only `instruction.md` and `docs/hardening-spec.md`)._

## Difficulty Explanation

`mailguard` replays a batch of observed inbound connections through each domain's published SPF record, scores SPF and DMARC posture, and emits hardened records. It never errors — it always writes a complete, deployable-looking result — but its verdicts are wrong in ways that leave the domains spoofable. Correctness demands the real RFC 7208 check-host() procedure, which is an order-dependent decision procedure, not a set-union. Evaluation walks mechanisms left to right and returns the first match, so the outcome and the DNS-lookup count both depend on the connecting IP; the 10-lookup and 2-void limits are charged along the path taken, meaning one record can Pass an early sender and PermError a later one. The famous trap is `include`: it authorizes a sender only when the included domain *itself evaluates to Pass* — an IP inside an included record's `-all` yields Fail, a No-Match that continues, and an include of a domain with no SPF record is a hard PermError. `exists` builds its query name by macro expansion (`%{ir}` reverses the IP for allow-list checks). None of this can be faked by unioning authorized ranges, and getting most of it right still ships a record that authorizes the wrong senders.

## Solution Explanation

This is fidelity to the shipped contract (`hardening-spec.md`), not reverse engineering. Four modules ship incomplete. `spf.ts` must implement check-host() with left-to-right short-circuiting, the include-returns-Pass rule (Fail/SoftFail/Neutral continue; None or no-record is PermError; loops are PermError), redirect governance, `a`/`mx`/`exists` matching, and the per-path lookup and void budgets. `macro.ts` must expand macros including the `r` transformer that reverses the IP labels, so reversed-IP `exists` allow-lists resolve the right name. `dmarc.ts` must raise the quarantine, weak-subdomain, partial-percentage and relaxed-alignment weaknesses and synthesise the full strict record (`p`/`sp`/`adkim`/`aspf`/`pct`/`rua`). `report.ts` must write canonical JSON with a string `report_version`, the hardened records at `zones/<domain>/spf.txt` and `dmarc.txt`, and the audit at the contract's paths. The hardened SPF record is derived from the evaluation itself — exactly the connecting IPs that pass today, minus flagged sources — so a wrong walk yields a wrong record. The other modules (canonical JSON, the DNS/feed clients, CIDR algebra, the config/scope loaders, the hardening assembler and the CLI) already ship correct.

## Verification Explanation

The grader is black-box: it serves the DNS resolver and the feed from mock HTTP servers seeded from a generated zone database, runs the compiled tool through a subprocess, and compares every artifact against an independent Python reimplementation of check-host(), the budgets, macro expansion, CIDR canonicalization, the feed subtraction, DMARC scoring and the exact byte layout. The report and the zone files are matched byte for byte. Hard-coding is defeated by minting fresh estates from seeded RNG at grade time — spanning short-circuit matches, include chains that Pass, Fail or PermError, lookup-limit and void-limit overflows that depend on the IP, macro `exists`, redirects, ptr, and every effective-all disposition and DMARC weakness — with the expected output recomputed from their bytes, plus an anti-cheat pair asserting identical inputs are byte-stable while flagging a source changes the hardened record. Targeted cases pin each treacherous rule: short-circuit lookup counting, include-returns-Pass versus membership, include-of-missing PermError, IP-dependent lookup and void overflow, the reversed-IP macro, redirect results, hardening from the passing set, and the byte layout. The shipped tool fails 19 of the gradeable tests while the human-written oracle passes them all, and a local 60-seed byte-parity sweep confirms the reference agreement.
